# nix-config

System Flake for this machine: NixOS on WSL2, host `nixosConfigurations.136kf`, branch `wsl`, remote <https://github.com/zjm54321/nix-config>.

## Layout

- `flake.nix` / `flake.lock`: inputs and outputs; `module/ai/skill` is a local `path:` sub-flake (`skills-catalog`) for agent skills.
- `host/`: NixOS host configuration. `module/`: shared NixOS and Home Manager modules. `home/`: Home Manager configuration.
- `home/core/ai/agent/opencode/`: OpenCode V2 config (`opencode.json`, `oh-my-opencode-slim.json`, plugins, providers, the global `AGENTS.md` template). `opencode1/` is the V1 config deployed under `~/.config/oc1`.
- `/etc/nixos/src` is a read-only snapshot generated by the deployed system; edit this checkout, never the snapshot.

## Workflow

Use the `Justfile` recipes rather than re-creating them by hand:

- `just switch`: rebuild and activate (`nixos-rebuild switch --flake path:.#$(hostname) --sudo`).
- `just fmt` / `just check` / `just health`: format, `nix flake check`, and verify the activated system (`systemctl is-system-running` must be `running`).
- `just update`: update all flake inputs. To bump specific inputs only, run `nix flake update --flake path:. <input>...`.
- `just push`: push with GitHub CLI credentials. Push only when the user asks.

**System update requests:** when the user asks to update the system, deploy, and commit (for example, "更新系统然后部署提交"), run `just system-update`. It requires a clean worktree and runs update → fmt → check → switch → health → commit → cleanup (keeps 3 generations, then garbage-collects). Use this aggregate recipe as-is instead of splitting it up, unless the user explicitly asks for a different workflow. It does not push.

For configuration changes, edit, then `just fmt switch health`, then commit with a conventional message. Stash or commit unrelated work before `just system-update`, because its commit step runs `git add --all`.

## Conventions

- Pin plugins and tools to explicit versions; record the reason when a version is intentionally held back (for example `billion-context` is frozen at `v0.1.194`).
- Remove now-unused bindings and inputs together with the feature that used them, and refresh `flake.lock` for the affected inputs.
