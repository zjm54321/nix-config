# Environment

This machine runs **NixOS inside WSL2** on a Windows host. Both facts shape how to work here.

## NixOS

- NixOS is not FHS. Do not assume binaries or libraries exist under `/usr/bin`, `/usr/lib`, or `/lib`; resolve tools through `PATH`, Nix packages, and store paths.
- Software that is not installed is not missing from the system by accident. For one-off use, run `nix shell nixpkgs#<package>` (or `nix run`); do not install it permanently with `nix-env` or `nix profile`.
- For project development, declare the toolchain and dependencies in the project's `flake.nix`, commit `flake.lock`, and enter the environment with `nix develop`.
- Prebuilt dynamically linked binaries (pip wheels with native code, downloaded executables, npm postinstall binaries) may fail to run; prefer the nixpkgs package or a flake dev shell.
- Permanent software and system changes belong in the system Flake repository (<https://github.com/zjm54321/nix-config>, checked out at `~/nix-config`, host `nixosConfigurations.@systemFlakeHost@`). Follow that repository's own `AGENTS.md` for how to change and deploy it.
- `/etc/nixos/src` is a read-only deployed snapshot. Never modify `/nix/store` directly.

## WSL2

- Windows drives are mounted under `/mnt` (for example `/mnt/c`, `/mnt/d`). Files there are slower and use Windows permissions; keep projects on the Linux filesystem.
- Windows interop is enabled and the Windows `PATH` is appended, so `powershell.exe`, `cmd.exe`, `explorer.exe`, and `clip.exe` run from the shell. Convert paths with `wslpath -w` / `wslpath -u` when passing them across.
- `xdg-open` is not installed. To open a file or URL for the user, use `explorer.exe "$(wslpath -w <path>)"` or the Linux `google-chrome`.
- GUI apps run through WSLg (`DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-0`). systemd is enabled, so `systemctl` and user services work normally.
- Networking, `/etc/hosts`, and `/etc/resolv.conf` are generated by WSL; the hostname is `@systemFlakeHost@`.
